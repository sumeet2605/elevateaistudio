# Architecture

## Repository structure

| Path | Responsibility |

## Day 1 data flow

The browser sends a multipart upload directly to FastAPI. The upload handler stages it in the project folder, computes a SHA-256 fingerprint, and checks the video stream, dimensions, and duration with FFprobe. The subprocess receives an argument list built by the backend. The project ID is a UUID and the stored filename is generated by the backend. Names supplied by users are display metadata.

The staged file is moved to a unique, read-only source path. SQLite attaches it using a conditional update that succeeds only when the project has no source. If two uploads race, the losing request removes its own file. Normal failures clean up staging files. A hard process exit can leave an unreferenced file in the project directory. It cannot replace the registered source. The original endpoint serves the registered bytes and supports byte ranges so a player can seek.

## Day 2 transcription

The API commits a queued job to SQLite and responds with HTTP 202. A separate worker claims the oldest queued job. A partial unique index enforces one active transcription per project even if two requests arrive together. A data-directory lock allows one worker per database on macOS or Linux. On start, that worker marks abandoned running attempts interrupted, or cancelled if cancellation had already been requested. Queued jobs remain available. Retry creates a new attempt and preserves the old record.

FFmpeg extracts the first audio stream as 16 kHz mono PCM into a per-attempt WAV. The audio filter fills leading offsets and discontinuities relative to the input's common start. Python reads the PCM into a sample array for Faster-Whisper. The worker loads the model lazily and reuses it. Faster-Whisper detects the language and transcribes the spoken content with word timestamps and optional voice activity detection. VAD filters inference input only. Source video and WAV playback time remain intact.

The version 1 transcript schema carries the project UUID, source SHA-256, model, detected language and confidence, source duration, transcript text, segments, words, and creation time. It validates ordered source-relative seconds and bounds every word inside its segment. The worker reconciles small model boundary overlaps before validation. It writes and flushes a staged JSON file, then renames it as part of the SQLite publish operation. The API serves the artifact only after the database commit. Each successful attempt preserves a distinct transcript version. The browser polls while a job is active and seeks the existing video element directly when a timestamp is selected.

## Day 3 analysis and review

The durable queue now dispatches transcription and audio analysis. The partial unique index permits one active job of each type per project. Analysis snapshots the saved settings and the latest available transcript at enqueue time. Retry uses the same snapshot. The existing worker remains responsible for progress, cancellation, and interruption recovery. Measurement reports the fraction of PCM frames read. FFmpeg silence detection and VAD report their actual processing stage.

The worker aligns the PCM to source time, measures it, runs FFmpeg amplitude detection, and unions Silero speech ranges across channels. It then protects detected speech and transcript words with an extra 50 ms guard and considers only the remaining gaps. Low-amplitude gaps checked against an available transcript can be high confidence. Other eligible gaps stay ambiguous. Settings enforce minimum pause, padding, and removable duration. Manual adjustments stay within the candidate and keep the minimum removable duration.

Evidence includes up to 600 waveform buckets and the quiet and speech intervals. The worker flushes a staged JSON artifact and renames it before the SQLite transaction publishes the plan. The evidence cache keys off source SHA-256, algorithm version, threshold, minimum silence, and noise adaptation. Changing padding or adding a transcript can reuse the evidence. Regeneration creates a new pending plan while retaining prior reviewed plans. Review decisions and approved cuts are written in one SQLite transaction.

The editing plan uses integer milliseconds and half-open ranges. Source timestamps inside removed ranges map to null. The source endpoint maps to edited duration. At an internal edited seam, the reverse mapping chooses the next retained source range. The edited endpoint maps to the end of the final retained source range. The approved cut union determines retained spans and estimated duration. The original and transcript use their existing immutable storage.

## Day 4 brand and director

Brand changes append immutable per-project revisions. Playbooks are versioned, schema-validated configuration files. Director jobs snapshot the chosen brand, playbook, transcript, approved and rejected silence decisions, source metadata, model, and pricing on enqueue. The prompt includes timestamped transcript data and editing constraints. The backend binds the result to project-local revision IDs and the original SHA-256. There is one active director job per project and up to two explicitly requested retries per generation.

The backend uses strict Responses API JSON Schema with no tools. It separately validates source bounds and identity, exact word timing, candidate boundaries, same-layer overlaps, brand zoom and audio constraints, and playbook zoom frequency. It rejects operations crossing existing or proposed cut ranges. Additional cuts must be inside pending high-confidence Day 3 proposals. Hook and caption text are assembled only from indexed transcript words. Hook and B-roll decisions remain advisory. A caption emphasis decision carries a range and words for future rendering. Brand outro text is never inserted as dialogue.

Every generation, review, or restore creates a new project-scoped revision. Approved silence ranges form the base. Accepted director cuts extend that base, and accepted events use the existing timeline mapper to derive edited time. The active pointer changes without rewriting old revisions. A silence plan change makes old director revisions read-only and blocks their reviewed export until a fresh draft is generated. Token accounting is attached to jobs separately from validation so billed invalid responses remain visible.

## Day 5 render and approval

A render request snapshots a validated manifest using the current immutable director revision, the transcript hash, source SHA-256, brand and playbook revisions, approved cuts, accepted emphasis, and output settings. The existing worker claims the attempt, verifies the source, writes the UTF-8 ASS asset, and compiles an FFmpeg argument array. No model output can become a command, path, filter expression, codec setting, or shell argument. A one-pass graph trims all ranges and concatenates them before applying captions and the final H.264/AAC encode.

Video and audio use the shared source clock. On the 30 fps render grid each retained start rounds up and each retained end rounds down. The audio uses the matching integer sample offsets at 48 kHz, with short seam fades. Tagged HLG and PQ sources are tone-mapped to BT.709 SDR using zscale before ASS captions are drawn. Missing audio at the source tail is padded with silence. The caption mapper accumulates the actual retained frame lengths and uses this clock to split cues and place words. ASS centiseconds use downward rounding for consistent non-overlap. Media timing can differ slightly from the exact authored plan at each seam.

Each completed attempt lives in its own directory with the render manifest, ASS file, metadata, and preview. The worker verifies codecs, dimensions, duration, and audio/video length before publishing. It atomically renames the staging directory inside the SQLite completion operation. Cancellation kills FFmpeg and removes temporary output. Crash leftovers stay isolated under their attempt IDs. Retry uses a new attempt and the same validated snapshot while it is current.

Preview, approval, and final export are separate. Approval records the exact MP4 checksum and plan fingerprint. Final export verifies the current revisions and both the original and rendered checksums. A rejection revokes the approval, while older decisions stay in the audit table. The browser can play historical previews for comparison.

## Planned editing decisions and time mapping

Use integer milliseconds on the source timeline with half-open intervals, where the start is included and the end is excluded. A validated plan will contain keep ranges, suggested removals, caption text and spans, keyword highlights, zoom ranges, B-roll suggestions, audio adjustments, and an output specification. The backend will reject out-of-bounds or conflicting decisions and verify that each executable event is supported. Suggestions such as B-roll remain reviewable until matched to a local asset. Model responses supply data only. Rendering code owns every executable, filesystem path, and FFmpeg argument.

Store accepted keep spans in source order. For each span, add the lengths of the preceding retained spans to get its start on the edited timeline. Within that span, subtract its source start from the event timestamp, then add its edited start. Split an event around a cut by intersecting it with each retained span before mapping. For example, keeping source 2–5 s and 9–11 s puts source 10 s at edited 4 s.

Save the original, the transcript, and immutable plan and render revisions separately. Bind human approval to the reviewed revision before publishing. A new edit creates a new revision, so undo can restore an earlier selection. Extend the local worker and SQLite job records when rendering lands. Give each render attempt a unique output directory and publish artifacts only after success.

## Day 7 caption revisions

The caption workspace builds draft cues from the pinned transcript and frame-aligned retained ranges. Cue times are canonical edited milliseconds at 1×. Revised text, timings and emphasis live in immutable caption rows tied to the director revision, with the source and transcript identities and a before/after correction log. The active caption revision and its digest join the approval fingerprint. Caption changes stale prior approvals while keeping prior preview bytes accessible.

The worker retimes the chosen revision to output speed before compiling ASS. Each cue or word-boundary event uses the same positioned line layout. HarfBuzz/libass shapes mixed scripts using bundled Noto faces. Animation is derived from cue time so an active-word update does not reset the fade or pulse. The HTML phone preview uses the original video and edited-to-source mapping with approximate CSS typography.

## Camera motion and local face analysis

`motion_native/detect.swift` runs Apple's Vision face-rectangle detector on temporary, upright FFmpeg samples. The worker limits sample rate to 1–3 Hz and stores source-relative sample times, normalized upper-left rectangles and confidence. Cached analyses are indexed by the original's SHA-256, the detector and OS version, and sampling settings. Temporary JPEGs are removed when the job exits. The app stores face rectangles only for framing. Director requests contain aggregate counts and existing editorial event decisions.

`motion_store.py` stores immutable camera snapshots in SQLite with their source, director, brand, playbook and optional face-analysis identifiers. A new snapshot supersedes the current revision for that director plan. A render pins the snapshot and its digest. Saving new motion invalidates old export approval while preserving previews and review history.

The track accepts a single reliable face, holds its last reliable focus across missing or ambiguous frames, and starts from a static focus before the first reliable sample. A continuity threshold, dead zone, and bounded smoothing reduce jumps. The crop stays within the upright frame and uses extra headroom when space is available. Multiple people can be framed with fit or a manually set point. There is no automatic identity selection.

`motion_render.py` maps accepted source intervals to the concatenated 30 fps frame clock before playback speed changes. It rejects events spanning a removed interval and accepted events that overlap. Small smooth ramps start and end at normal framing within the event. A hard punch deliberately changes at the event boundary. A source cut can change the tracked composition with the shot. Quantized, bounded FFmpeg expressions use approved numbers and enums, with no model-provided commands or paths. Camera transforms precede speed adjustment and ASS burn-in, leaving subtitle position and the audio clock independent of zoom.
